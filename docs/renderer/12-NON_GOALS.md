# Renderer V2 — Explicit Non-Goals

> Parent: [README.md](./README.md)  
> Vision: [01-VISION.md](./01-VISION.md)

Permanent scope boundaries. Capabilities listed here will **intentionally never** be implemented in the renderer unless a future ADR explicitly reverses a specific item.

---

## Document and content editing

| Non-goal | Why |
|---|---|
| **Word processor** | Official content is generated and immutable; editing belongs in the build pipeline, not the browser |
| **Google Docs–style collaboration** | Single learner; no multi-user document model |
| **Track changes / revision history on official content** | Provenance lives in build artefacts, not learner UI |
| **WYSIWYG markdown editor** | Projections are generated, not authored in the renderer |
| **CMS / publishing workflow** | No editorial roles, no draft/publish states in renderer |

---

## AI and medical intelligence

| Non-goal | Why |
|---|---|
| **Medical AI / chat tutor** | Medical reasoning belongs upstream; renderer displays results |
| **"Explain this" AI on selection** | Would blur immutability and require medical QA in browser |
| **AI summary of chapter** | Generation is batch pipeline responsibility |
| **OCR / vision on Personal Diagrams** | Contract explicitly forbids (C.8) |
| **Semantic search over learner notes** | Notes never feed AI (Part B learner layer boundary) |
| **Adaptive content rewriting** | Future adaptivity reads events; never writes projections |

---

## Assessment and memorisation (in renderer)

| Non-goal | Why |
|---|---|
| **QCM engine in renderer core** | Mastery projections are a separate family — renderer renders them, does not own logic |
| **Spaced repetition scheduler** | Future adaptive layer, keyed by KP ID |
| **Flashcard authoring** | Build pipeline generates mastery artefacts |
| **Progress analytics dashboard** | Future scope; renderer emits events only |

These may appear as **projection types** the renderer displays. They are not renderer-owned subsystems.

---

## Visual authoring

| Non-goal | Why |
|---|---|
| **Visual diagram editor** | SVGs generated by lou-build or manually checked in |
| **Runtime SVG generation from Blueprint** | Build-time concern |
| **Drag-and-drop graph editing** | Would mutate official visuals |
| **Colouring official SVG nodes** | Implies semantic learner edits to official diagram |

Learner **overlay** annotations on SVGs ([07-SVG_ANNOTATIONS.md](./07-SVG_ANNOTATIONS.md)) are planned — they are overlays, not edits.

---

## Platform and infrastructure

| Non-goal | Why |
|---|---|
| **Native mobile app** | Progressive web sufficient for V2; native is separate product decision |
| **User accounts / authentication** | Single learner, local-first |
| **Cloud sync as default** | Local IndexedDB; optional export is acceptable later |
| **Commercial SaaS dependencies** | Technology strategy constraint |
| **Server-side rendering** | Static artefacts + static renderer |
| **Real-time collaboration WebSocket** | Not a collaborative product |

---

## Content ownership blur

| Non-goal | Why |
|---|---|
| **Storing modified projections in Git** | Violates immutable official content invariant |
| **Learner annotations in chapter repository** | Learner layer outside content tree |
| **Merge learner notes into regeneration input** | Notes never input to generation |
| **Community-shared highlights** | Not social; personal study tool |

---

## Scope creep signals

Reject feature requests that match these patterns:

- "Can Lou edit the walkthrough to simplify it?" → Triggers **regeneration** via feedback, not in-browser edit
- "Can we add comments for a tutor to see?" → Collaboration non-goal
- "Can the renderer generate a quiz from this section?" → Mastery projection generator in build pipeline
- "Can we use ChatGPT in the margin?" → Medical AI non-goal
- "Can students share diagram annotations?" → Collaboration non-goal

---

## What IS in scope (sanity check)

The renderer **will**:

- Display manifest-driven projections
- Render pedagogical blocks with optional Official Visuals
- Provide source traceability lookup
- Store Personal Diagrams, Inline Notes, text selection annotations
- Support responsive reading and SVG zoom
- Degrade honestly when content or anchors change
- Emit learner interaction events for future adaptivity

When in doubt, ask: **does this display or personalise existing artefacts, or does it create/modify medical content?** Only the former belongs in the renderer.
